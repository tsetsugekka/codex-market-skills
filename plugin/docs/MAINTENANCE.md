# Plugin 维护与构建

`plugin/` 是商店版权威源码；根 `skills/` 是独立 Codex 工作流。两者允许不同运行适配，但不以适配为由删除研究方法。保留稳定包名 `codex-market-skills`、展示名 DayTrading.Monster 和现有商店身份。

## 来源与包边界

- `plugin/skills/`：十项插件入口、跨环境能力路由及插件专用研究细则。
- `plugin/shared-references.json`：从根 `skills/` 原样收集的研究长文白名单。主题生命周期、完整情绪与技术框架、策略类型及主线/资金/博弈/周期只维护一份正文。
- `plugin/shared-scripts.json`：从根 `skills/` 原样收集五个标准库 Python 脚本；另有插件专用的掲示板离线输入入口，共六个脚本。采集与离线筛选复用同一函数，不复制一套算法。
- 插件源码用可点击相对路径引用共享文件。构建器将白名单内容放入 ZIP 内各 Skill 的 `references/`，只转换链接位置，不删改方法正文。不会在运行时访问 GitHub 才能取得参考。
- `.codex-plugin/`、`assets/`：商店清单与图标。根同名目录继续服务独立 Codex 版，不代表商店最新版本。
- README、工作原理图、构建器、测试和维护文档不进入发布包。便携 Python 进入包，OpenD 采集器及供应商 Skill、SDK、凭据不捆绑；[环境路由](../skills/market-daily-strategist/references/runtime-capabilities.md)列出脚本用途、网络条件和副作用。

## 方法覆盖与差异

| Skill | 恢复并保留的方法 | 插件适配 |
| --- | --- | --- |
| 市场策略 | 三市场盘前/收盘/长线、六类收益来源、主线/资金/博弈/周期、可成交复盘 | 不固定私人标题、推荐数量、持仓或归档位置 |
| A股盘面 | 题材加权/覆盖、资金口径、分钟图、涨停广度、调研日期、跨轮比较 | 按当前可用来源取证，不强制本机供应商 |
| A股异动 | 七阶段、期待差、共振、EPS×PE 情景与情绪溢价 | 保留公开报价与已有任务材料复用 |
| 日股异动 | 财报/指引/资本政策、PTS推定成交额、掲示板100→24/72小时→评分去重20→最新5条、估值 | 同一算法支持联网和离线；无执行能力时如实标明完成范围 |
| 美股异动 | 事件时间线、指引与价格接受、同业/ETF、期权/资金/社区、融券 | 按权限选择 moomoo 或其他工具，区分缺数据与无异常 |
| 宏观 | 新闻/价格双流、六种关系、传导链、跨资产与市场结构 | 不依赖本机安装或固定仪表盘读取能力 |
| 情绪 | 完整框架、六因素共振、主线/跟随、拥挤与反证 | 不自动修改经验文件或读取账户 |
| 技术 | 完整手册、结构/指标/量价、执行现实、事件溢价与计划一致性 | 数据序列或截图按实际环境取得 |
| Gamma | GEX模型/flip、Vanna、分期限/逐日期、代理锚、情景表、热力图 | 完整输入与计算工具可用就计算；不足时有限解读，不强制OpenD |
| 财经日历 | 美日财报/宏观、筛选、期待差、DST、去重/合并/回读 | 不自动读取私人自选，不伪造未公布分钟；连接可用且授权才写 |

旧独立版中的自改 Skill、私人偏好、本机安装/沙箱要求不会复制到插件。来源取证、模型假设、深度参考和反证仍须保留。独立版研究规则变更时，检查上表对应入口与共享参考；插件专有运行适配修改不要求覆盖独立版。

## 构建与验证

在仓库根执行，输出到仓库外的临时或指定发布目录：

```bash
python3 plugin/build.py /tmp/daytrading-monster-0.1.11.zip
python3 -m unittest discover -s plugin/tests -p 'test_*.py'
```

构建器验证十个 Skill 的名称、描述、允许文件类型、私人信息模式、共享引用和包内链接。对解压后的实际发布包再运行 Skill frontmatter 与插件清单验证；审查新增正文及共享文件是否含个人数据。静态验证不代表行情连接、研究输出质量或定时任务加载已通过。

包测试覆盖可重复构建、共享内容一致性、脚本语法与包内链接；掲示板测试覆盖原始条数先于点赞过滤、24/72小时、评分/去重/最新五条、跨年时间、采集结果不暴露100条原文，以及禁网子进程中的离线命令。对实际包的六个脚本逐个执行 `--help`，另验证离线期权表的到期内在价值。

发布前运行[场景检查](../../docs/plugin-submission-tests.md)，记录实际环境、取得资料与结果；未执行的场景标未验证。上传完成后核对版本、附件与平台扫描；正式提交涉及的法律声明按平台要求由维护者确认。只有看到 Published 才更新[发布状态](../../docs/plugin-compatibility.md)。不手动覆盖宿主缓存，也不根据普通对话推定 Scheduled Tasks 已加载。
