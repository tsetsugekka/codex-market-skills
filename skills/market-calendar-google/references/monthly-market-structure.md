# 每月到期、交割与日本 SQ 维护

在用户要求维护定期市场日程，或已授权的财经日历周期任务运行时读取。它补充周历流程，不改变财报排程和筛选规则。

## 范围与日期依据

沿用用户已选市场及现有类别，至少核对相关的股指期货/期权交割、期权到期、A50 期货、日本月度 SQ 与 SQ 前星期三。美国期权到期、季度集中到期及 VIX 期货等仅在用户范围内维护，不自动扩成所有合约日历。

先明确交易所、产品和日期含义：最后交易日、到期日与最终结算日可能不同。名称含混的中国“股指期权交割日”须核对原事件所指中金所指数期权还是沪深交易所 ETF 期权，不能仅凭每月第几个星期几归类或合并。保持用户标题，必要时在详情简短注明产品。

日期优先使用对应交易所的当期到期/交易日历与合约规则：中金所（股指期货及指数期权）、上交所/深交所（ETF 期权）、SGX（富时中国 A50）、JPX/OSE（日本 SQ）、Cboe/CME/OCC（对应美国产品）。年度日历可缓存复用，记录适用年度及读取日期；每月核对新月份和交易所修订，不重复逐项抓取已核月份。节假日按该产品交易所规则调整，不用一般工作日替代交易日。

日本月度 SQ 通常对应第二个星期五，休业日按 JPX 调整。先确定实际 SQ，再确定该周星期三；“SQ前の魔の水曜日”是市场观察标记，不是交易所另设的交割日。不能独立设成每月第二个星期三：例如 2026-10 的 SQ 为 10/9，对应星期三为 10/7，而第二个星期三是 10/14。月份从周四、周五开始及节假日调整必须纳入核对。

## 滚动维护

- 默认检查当月及未来两个月；用户指定更长范围时从其要求。每次既有日历任务启动，先检查覆盖截止月；月度换窗或来源修订时才补研究和写入，无变化不重复创建。Skill 本身不是调度器。
- 先分页读取目标日历的整个窗口，并读拟修改事件及其重复母规则、例外。按市场、产品、事件类型和日期对账，记录已存在、需改、需补与待核实项；标题相近不代表同一事件。保留人工修改及原日历位置，不自动迁移历史事件。
- 这类日期标记采用全天、紫色（Google event color_id 3，使用前核对色卡），保持空闲、关闭提醒；不是 00:00 的定时约会，也不用 08:00/10:30 占位。全天写 start.date 与次日 exclusive end.date，不做 UTC 时刻转换；明确发布时刻的经济数据与财报仍遵循各自规则。
- SQ 前星期三采用逐月明确日期的独立事件，不保留无限第 N 星期三规则。其他类别只有重复规则能准确表达交易所规则和例外时才使用系列，否则也逐月创建。修复错误系列时先读全部受影响范围，保留已核日期，停止错误未来展开，避免新旧重复。
- 详情只保留事件含义、相关产品和必要市场提示，不填排程来源链接、抓取过程或内部校验记录。来源、时效及已核截止月保留在私有工作记录中。
- 能力不足或写入失败时，报告具体未完成项并保留日期清单。工具有全天参数不等于转换已成功；经授权的普通界面可处理能力缺口，权限拒绝或明确取消则停止受影响操作，不换通道绕过。
- 写后回读实际日期字段、全天状态、紫色、提醒、重复规则及展开结果；确认窗口内每类每月覆盖，无旧错位实例和重复项。未确认未来月份列为待核实，不用无限重复假装覆盖。

## 接入已有定时任务

用户授权持续维护时，更新负责财经日历的原有任务 Prompt 与实际 Skill 入口，加入本 Reference 的读取触发和滚动窗口；保留任务 ID、频率、时区及启停，不另建重复任务。每周、补充和每日入口应采用同一规则，避免后续任务改回占位时刻或错误重复。

从真实调度器回读保存后的 Prompt/配置，并确认执行环境能读取这份 Reference。源码发布、安装包更新、运行时读取及日历写后验收分别报告；不能用 GitHub 提交或本地镜像代替运行时验收。
