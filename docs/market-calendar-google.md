# Market Calendar Google

`market-calendar-google` 是一个用于 Codex 的市场日历 skill。它把美股财报、日股财报、中美日宏观数据、央行事件、美债拍卖和其他重要市场事件整理成 Google Calendar 日程。

skill 目录里的 `SKILL.md` 是给 Codex 执行时读取的规则文件；本文档是给 GitHub 用户阅读的公开说明。

## 能做什么

- 整理指定周的 Earnings Whispers 美股财报日历。
- 根据用户提供的美股或日股关注列表筛选重点财报。
- 整理中美日重要宏观数据、央行事件、拍卖和财经事件。
- 在既有定时任务中滚动维护当月及未来两个月的期权到期、交割和日本 SQ 日期标记：全天、紫色，按交易所及节假日核对，SQ 前星期三逐月确定。详见[公共维护 Reference](../skills/market-calendar-google/references/monthly-market-structure.md)。
- 按用户本地时间写入 Google Calendar。
- 自动合并同一 30 分钟时间段内的多个事件。
- 为五星事件设置醒目的 Google Calendar 颜色。

## DTM API 接入

DTM 候选池改用 API Docs 的 `https://daytrading.monster/api/themes?market=jp` 和 `https://daytrading.monster/api/themes?market=us`，读取 `themes[]` 及其 `constituents[]` 的代码、名称、权重和 `reason_zh`。个人名单优先级不变；该接口不提供财报日期。这些正式接口见 [API Docs](https://daytrading.monster/api-docs/)，响应正文按 JSON 解析。

## 本地偏好 Reference

保留两层独立资料：公共 Reference 保存通用方法，随 Skill 发布到 GitHub；Private Reference 保存每位用户自己的偏好，在各自本机单独创建和维护，不进入发布包。

支持查看、保存、修改和删除个人偏好，例如「把这条摘要格式记为以后财经日历的默认偏好」「查看已保存的财经日历偏好」「删除摘要长度偏好」。只维护偏好时需要本地文件访问，不需要连接 Google Calendar。

入口按私密索引复用仓库外的 `calendar-preferences.md`；尚未建立时创建文件并登记索引。记录用户明确表达的偏好、适用范围和更新日期，后续按「本次要求 → 已保存偏好 → 公共默认」应用。单次调整不自动变成长期偏好；保存偏好不自动改写已有日程。摘要结构、详略、关注重点以及其他设置均可记录，具体个人内容不上传 GitHub 或发布包。

## 需要的权限和来源

- 需要 Codex 的 Google Calendar 连接器来创建或更新日历事件。
- 会在需要当前事件、财报或共识数据时读取公开网页或公开日历来源。
- 首轮先完整发现候选，再筛选：综合经济日历覆盖定时数据；主动查找目标周的中文周报及日本市场周历，发现产业、政策和市场结构催化；最后用机构、公司 IR、交易所及主办方来源核验。多篇转载不算独立覆盖。
- 金十数据和华尔街见闻可作为中文市场周历和市场叙事来源，用来补充地缘、油价、黄金、通胀预期、港股/中国市场语境等候选事件。
- 用户提供的财经文章、长图和截图会完整检查正文、表格、嵌入图片和图注；它们用于发现候选，不会被机械整页写入日历。
- 四星和五星事件写入 Google Calendar 前，应尽量用官方来源或另一高可信财经日历交叉确认时间和事件内容。
- 不需要本地 API token。
- 不会自动读取 `.env` 或其他凭据文件。

## 输出和写入规则

- 默认用中文写日程详情。
- 央行官员讲话在人名旁简短标注其一贯的鹰派／偏鹰／中性／偏鸽／鸽派印象，必要时补人物近期转向，依据不足标倾向不明。标的是讲话者本人，不是尚未发生的这次讲话。
- 默认使用运行环境中的用户本地时区；如果无法确认，则在写入前询问目标时区。
- 日股财报直接用 SBI 选定周的预计日期和可用时刻排程，不逐家公司查官方 IR。历史时刻可作为本期预测，详情简短标「参考／预计」；按日本时间转换后分入30分钟组。SBI没有时刻且没有已确立的例外时才用08:00占位。仅用户专项要求或已有具体冲突时查官方，不把历史参考误称本期官方保证。
- 美股财报先采用本期官方精确发布时间，其次采用可靠财报来源的具体时刻；只有来源仅给盘前／盘后时才用对应时段锚点。海外公司按发布地的日期和夏令时换算，财报发布与电话会分开；时区缩写冲突须交叉核实，不能退回任意 08:00 占位。
- 财报验收同时核对公司代码覆盖和合并事件数，逐股比对来源时刻、时间类型、时区换算及实际日历开始时间。重复发生的问题还需确认实际加载版本与定时任务 prompt，回读更新后的实际入口；改完一周日程不等于后续规则已生效。
- 日程详情不放任何研究资料或排程来源链接，包括人物立场参考、官方资料、SBI、公司 IR、交易所、新闻与报告链接；不填来源过程说明。来源保留在后台工作记录，日历只保留事件信息、必要的参考／预计标记和市场影响。
- 写入日历前应先搜索同一周已有事件，避免重复。
- 用户指定已有日历时，先列出日历并解析唯一的 `calendar_id`；查重、写入和回读均使用这个 ID。未指定时使用 `primary`，不保存私人日历 ID，也不假定当前连接器支持新建日历或跨日历迁移。
- 分别判断交易重要性、事件确认程度和时间精度。覆盖利率汇率与流动性、需求及产业链、公司催化、政策与市场结构后，再形成精选日历；不能因没有具体时刻、来源未标星或事件在其他国家就直接判为低价值。
- 工作候选表记录来源与时效、时间和时区、资产传导、入选／已存在／排除理由／待核实。写入前检查覆盖缺口，补充时区分首轮遗漏、新公告、预测或时间修订和范围变化；写入成功不等于研究完整。
- 对没有精确时刻、但已确认且足够重要的会议、产品发布或政策节点，可按用户既定习惯在本地时间 `08:00` 创建 0 分钟提示；多日活动只创建首日，并在标题标明日期范围。
- 数据发布、央行沟通、市场结构事件、产业/公司催化剂和已确认政策事件会分别判断；财报不会与宏观事件合并为同一日程。
- 日程写入后会再次检索确认。预期值更新须核对指标口径和调查时点，区分市场共识与机构预测；正文／配图冲突先核查，不能仅因文章更新就覆盖原值。
- 只在用户明确要求写入 Google Calendar 时创建或更新日程。
